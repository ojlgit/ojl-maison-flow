# 15 - Render-to-WebGL Pipeline

## Purpose

This file defines how generated ComfyUI outputs, local 3D models, and WebGL runtime assets move from idea to approved production components.

The target is an automated AI process where:

- real OJL jewelry GLB files stay central
- ComfyUI creates supporting premium visual elements
- agents organize, inspect, optimize, and manifest assets
- the website loads approved elements through data contracts
- the no-scroll forward-camera experience stays intact

## Pipeline overview

```txt
1. RoomSpec
2. RenderBrief
3. ComfyUI generation
4. Candidate sorting
5. Refinement / inpainting / segmentation / upscaling
6. Human or agent selection
7. Asset card
8. Optimization
9. Manifest entry
10. WebGL placement
11. QA
```

## Stage 1 - RoomSpec

A room spec defines the role of the room, its hero product, its visual world, and required components.

Use template:

```txt
templates/ROOM_SPEC.md
```

Required information:

- room id
- hero product asset key
- story goal
- camera entrance/hero/exit intent
- floor type
- table/plinth type
- wall/background type
- lighting mood
- ComfyUI outputs needed
- GLB outputs needed
- runtime budget

## Stage 2 - RenderBrief

A render brief is the exact instruction packet for ComfyUI generation.

Use template:

```txt
templates/COMFY_RENDER_BRIEF.md
```

Briefs must avoid copyrighted style copying and must describe OJL original visual direction.

## Stage 3 - ComfyUI generation

Run the appropriate ComfyUI workflow:

- Flux/Krea/Dev for premium still concepts and material references
- Flux Fill/Qwen inpainting for targeted edits
- SAM3/BiRefNet for cutouts and masks
- upscalers for selected images
- LTX/Wan/Luma-style workflows for restrained atmospheric video loops

Generation outputs go first to:

```txt
assets_source/comfy/candidates/<room-id>/<component-type>/
```

Do not put raw generations directly into `public/assets/`.

## Stage 4 - Candidate sorting

Sort candidates into:

```txt
assets_source/comfy/selected/
assets_source/comfy/rejected/
```

Reject if:

- jewelry is fake or misleading
- visual competes with hero product
- contains text/logo artifacts
- resembles protected brand work too closely
- has obvious AI defects
- cannot tile or crop cleanly if needed
- too noisy for premium style

## Stage 5 - Refinement

Use ComfyUI refinements:

- inpaint visible AI defects
- remove text artifacts
- create clean masks
- remove background if creating cutout
- upscale only selected assets
- crop to power-of-two-friendly dimensions when useful
- create still fallback for every video loop

## Stage 6 - Asset card

Every approved runtime asset needs an asset card.

Use:

```txt
templates/ASSET_CARD.md
```

For AI-generated art components, include:

- source workflow
- prompt/brief id
- generation date
- seed if known
- license/safety status
- final runtime path
- usage scope
- room id

## Stage 7 - Optimization

Images:

- prefer `.webp` or `.avif` where supported
- keep dimensions appropriate to use case
- avoid huge 4K images for tiny planes
- create mobile variants when necessary

Video:

- compress aggressively
- create poster/fallback image
- keep loops short
- do not autoplay with sound

3D:

- GLB only for runtime
- run glTF optimization before production use
- texture compression where possible
- keep material count low

## Stage 8 - Manifest entry

Add approved art components to:

```txt
src/experience/assets/artComponentManifest.js
```

or equivalent manifest introduced by Hermes.

Do not hard-code paths in scene code.

## Stage 9 - WebGL placement

Use components according to their type:

- floor textures -> floor material maps
- table textures -> plinth material maps
- background plates -> distant planes
- sky plates -> sky dome or large curved plane
- cutouts -> transparent depth planes
- light masks -> emissive/alpha planes or shader masks
- video loops -> low-priority background planes only

## Stage 10 - QA

Run the normal site checks:

```bash
npm run build
```

Browser checks:

```js
window.scrollY === 0

document.documentElement.scrollHeight === window.innerHeight

document.querySelectorAll('canvas').length === 1
```

Visual checks:

- product remains center of attention
- background supports product
- no AI artifacts visible
- mobile is not overloaded
- console has no missing assets

## Rule for real jewelry files

Real OJL jewelry files are never generated by ComfyUI. They enter through the GLB asset workflow, are inspected with an Asset Card, and are placed through product anchors.

ComfyUI may create:

- reflections/backgrounds around the product
- material references
- product-safe hero plates for fallback only
- retouching references

But the WebGL hero product should use the actual approved 3D jewelry asset whenever possible.
